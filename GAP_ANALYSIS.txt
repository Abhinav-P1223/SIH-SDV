WHAT IS GENUINELY ENGINEERED
----------------------------
* Quintic lattice solves a real 3x3 boundary-value system via np.linalg.solve
  (candidate_generator.py:52-64) and seeds d''(0) from the actual steering
  angle rather than zero (line 141). Transition length is sized from three
  real constraints: steering limit, lateral acceleration, and v0*T_lat.

* Collision checking is a correct separating-axis test (core/geometry.py:67-80),
  with true polygon-polygon distance (95-103) and a conservative circumscribed
  radius bound. Genuinely batched: all C candidates x N steps stacked into one
  array, looping only over M objects.

* All 13 cost weights are live and consumed. scorer.py:65-114 populates
  collision, uncertainty, clearance, smoothness, curvature, jerk, progress,
  boundary, speed, lateral, consistency, front_pass, blocked — exactly
  matching CostWeights. No decorative weights.

* Four selection tiers all exercised in practice. Measured on
  dense_market_mixed_traffic: 21 degraded selections, 5 fallbacks. On
  narrow_lane_boxed_in: 38 degraded, 48 fallback, 53 reverse selections.

* Prediction is genuinely constant-acceleration with a self-estimated
  acceleration: a real least-squares slope over velocity history
  (predictor.py:121-129), low-passed, magnitude-clamped per class. Below
  min_history_samples it returns exactly zero and reduces exactly to CV.

* Risk engine computes three real views against real SAT footprint distances.
  TTC is not d/v_dot: first_overlap_time (58-70) is the earliest step where
  footprints truly overlap OR come inside the margin WHILE STILL CLOSING.
  CRITICAL is decided in exactly one place, from the physical view only.

* Behaviour FSM is genuinely declarative: state_machine.py:198-213 is a single
  ordered list of (from_states, to_state, guard) tuples, interpreted by a
  generic 17-line loop. No hidden if-ladder. Two independent hysteresis
  mechanisms: asymmetric dwell (escalations bypass min_dwell_s) and split
  entry/exit thresholds.

* Stanley is the genuine law with front-axle reference, signed cross-track via
  heading projection, real arc-length look-ahead, and curvature feed-forward.
  PID has correct CONDITIONAL anti-windup (longitudinal.py:72-74) — textbook,
  not decorative.

* Actuator saturation includes steering RATE limiting (actuators.py:38-43),
  which most prototypes omit. Control cannot bypass it: models.py:72 calls
  actuators.apply() unconditionally.

* Kalman filter has correct constant-acceleration process noise
  Q = q^2*[[dt^4/4, dt^3/2],[dt^3/2, dt^2]], not a fudged diagonal. Radar
  radial-speed update is a genuine EKF that linearises about the sensor-track
  unit vector and correctly subtracts ego velocity. Real Mahalanobis gating
  against chi2 = 9.21.

* Metrics computed from executed states against TRUE agent footprints, using
  exact SAT distance with correct edge-triggering.

* Frenet corridor accurate to sub-millimetre laterally. Measured on the R=60 m
  curve: arc length error 1 mm; round-trip max |dd| = 0.0004 m; lateral bounds
  error 0.4 mm. Cross-checked against an independent reference implementation.

* Determinism: bit-identical seeded replay asserted on full float lists.

DEFECTS FOUND, RANKED BY DAMAGE A JUDGE COULD DO
------------------------------------------------

1. GROUND-TRUTH LEAKAGE INTO THE SENSOR COVARIANCE
   simulation/sensors/models.py:157,192
   _polar_to_cov() is called with the TRUE range and TRUE bearing, not the
   measured ones. The tracker is handed an oracle-derived uncertainty — the
   single number a filter is most sensitive to. Verified with an exaggerated
   config: true range 40 m, measurement landed at 74 m, reported cov_yy =
   12.18 where a real sensor reports 41.70. Small at production noise levels,
   but it is literally on the project's own automatic-penalty list.

2. THE `blocked` COST IS STRUCTURALLY ZERO FOR TWO REJECTION CLASSES
   collision_checker.py:247 / 296
   route_block_severity is computed only for candidates still alive at
   section 5. Candidates rejected for boundary margin (section 3) or collision
   margin (section 4) never reach it. Measured over a full dense-market run:

     rejection class            scored   blocked>0
     FEASIBLE                     9300   5701 (61.3%)
     TERMINAL_STATE_EXPOSED       3950   1868 (47.3%)
     OUTSIDE_DRIVABLE_SPACE       2113      0 ( 0.0%)
     PREDICTED_COLLISION          1420      0 ( 0.0%)

   That weight is 3.0, second only to collision (6.0). Inside the degraded
   tier this hands squeezed candidates a systematic advantage of up to 3.0
   purely from evaluation order. THIS IS THE MOST CONSEQUENTIAL BUG FOUND.

3. THE METRICS COLLECTOR COMPARES MISMATCHED TIMESTAMPS
   simulation/runner.py:137
   Scores the ego pose AFTER vehicle.step (line 128) against truth captured
   BEFORE it (line 102), and world.update (line 129) has since moved every
   agent. Error up to 0.2 m at 10 m/s, 0.4 m at 20 m/s. Reported minimum
   clearances of 0.59 m and 0.67 m sit inside that band, and several tests
   assert clearance >= 0.5 m.

4. risk.levels.critical: 0.80 IS A PROVABLY DEAD CONFIG KEY
   risk_engine.py:239 assigns CRITICAL; lines 248-249 unconditionally
   downgrade it to HIGH. Verified by direct execution:
     score=0.30 -> MEDIUM   score=0.50 -> HIGH
     score=0.85 -> HIGH     score=10.0 -> HIGH
   Changing config/autonomy.yaml:50 has zero observable effect.

OTHER STRUCTURAL OBSERVATIONS
-----------------------------
* THE EGO STATE IS SIMULATOR-EXACT EVERYWHERE. self.ego from vehicle.step goes
  unfiltered into the planner, risk engine, controller, safety supervisor AND
  the sensor models. There is no localisation, no odometry drift, no IMU noise,
  no GPS. The stack knows its own pose to machine precision.

* THE DRIVABLE CORRIDOR IS HANDED OVER AS THE SIMULATOR'S OWN OBJECT.
  runner.py:78,81,113 pass the identical DrivableSpace instance the world uses
  into the predictor, planner and risk engine. For a problem statement about
  UNSTRUCTURED roads, the hardest perception task — inferring where the
  drivable space is, without markings — is skipped entirely.

* ERRATIC HAS NO CORRIDOR CONTAINMENT. Measured over 60 s on
  unmarked_village_road's cattle_1: y wandered from +2.29 to -11.59 on a road
  whose boundaries are +/-2.3 m, ending at d = -3.34, OUTSIDE the corridor,
  having also drifted 11 m backwards in x. A Brownian particle, not an animal.

* boundary_clearance returns EXACTLY 0.0 for anything outside (road.py:165),
  so the planner cannot distinguish "1 cm over the line" from "10 m into a
  field". No signed distance, no gradient to recover along.

* FEASIBILITY FED TO THE FSM IS ONE CYCLE STALE. runner.py:111 computes
  had_feasible from the PREVIOUS cycle's plan. g_emergency and g_boxed_in act
  on 100 ms-old feasibility.

* THE SAFETY SUPERVISOR IS STRUCTURALLY SILENT BELOW 1.5 m/s. Triggers 2 and 3
  are gated on min_speed_for_ttc_override_mps. Below that, only the fallback
  trigger can fire. Defensible (stopping distance < 0.2 m at crawl) but must
  be stated to a jury rather than letting them find it.

* SCENARIOS ARE TUNED TO THE STACK'S CAPABILITY, and the tuning is documented
  in the YAML comments themselves (sudden_pedestrian_dart.yaml:7-10 states
  outright that 19 m is "the survivable threshold"). That is scenario
  engineering, not ego scripting — but a jury should know. The repo does keep
  the 14 m failure on record, which is to its credit.

* NOTHING ABOUT THE EGO IS SCRIPTED. EgoSetup carries exactly three things:
  initial_state, desired_speed, desired_lateral_offset. No waypoints, no timed
  commands, no trigger-based ego actions, no override hooks anywhere. This
  claim survives scrutiny.

PART 4 — LEARNED PERCEPTION STRATEGY
================================================================================

THE STRUCTURAL PROBLEM, STATED PLAINLY
--------------------------------------
THE SIMULATOR HAS NO IMAGES. CameraModel.measure takes the true (x,y),
converts to range/bearing, adds Gaussian noise, converts back. There is no
pixel anywhere in the system. So "add a detector to the loop" has no natural
insertion point, and the two obvious approaches are both bad:

  * Rendering synthetic images and detecting rectangles you drew yourself is
    circular. It is exactly the "FAKE ML" automatic penalty in the project's
    own rubric (jury.txt:1024).
  * Bolting a COCO-pretrained detector onto a matplotlib render produces
    garbage and invites a devastating question.

THE APPROACH THAT ACTUALLY WORKS
--------------------------------
Split the claim into two halves, each independently true and checkable.

HALF ONE — OFFLINE AND REAL
  Fine-tune a detector on IDD, evaluate on a held-out split, and run it live on
  an Indian road clip during the demo. This makes "camera observations are
  processed by a learned object detector" literally true, demonstrated on real
  footage, with a measured mAP.

HALF TWO — CLOSE THE LOOP
  Take the detector's MEASURED statistics and replace the simulator's invented
  camera model with them:

    MEASURED FROM THE DETECTOR       REPLACES THE CURRENT INVENTION
    ---------------------------------------------------------------------------
    Per-class confusion matrix       Uniform draw over all other classes (a cow
                                     currently becomes a bus as often as a
                                     pushcart)
    Recall vs range and object size  Hard cutoff at 60 m with range-independent
                                     5% dropout
    False-positive rate              Zero clutter today
    Confidence distribution given    An unconditioned Gaussian draw
    correct/incorrect
    Localisation error vs range      A hand-chosen sigma_r = frac*r + min
    (from KITTI 3D)

  That converts FIVE of the sensor defects in Part 1 into measured quantities
  in one move, and produces a stronger sentence than the one requested:

    "The camera error model is not invented; it is measured from a learned
     detector evaluated on Indian road imagery."

  A judge can check it.

CLASSES
  Map IDD to the nine ObjectType values already in the enum: PEDESTRIAN,
  BICYCLE, MOTORCYCLE, AUTO_RICKSHAW, CAR, BUS, TRUCK, CATTLE (animal),
  PUSHCART (cart). The mapping is close to one-to-one, which is precisely why
  IDD is the right dataset.

ARE PRETRAINED WEIGHTS SUFFICIENT? NO.
  COCO has no auto-rickshaw and no pushcart, and those two classes are the
  entire Indian-road argument. Fine-tuning is necessary, but cheap: start from
  COCO weights, freeze the backbone for the first epochs, train the head.

  One fine-tune run on roughly 5,000-10,000 IDD images at 640 px, on the order
  of 20-50 epochs. Target mAP@0.5 around 0.35-0.50.
  THE GOAL IS NOT THE BENCHMARK. A modest mAP with an honest confusion matrix
  is worth more here than a high score, because the confusion matrix is the
  deliverable.

  * Held-out IDD split; report per-class AP and the FULL confusion matrix
  * Recall bucketed by box height as a range proxy
  * False positives per image
  * Separate KITTI pass for localisation error vs true 3D range
  * Publish all of it, INCLUDING the classes it does badly on

  2. A new standalone perception_demo path runs video frames through the
     detector into the EXISTING tracker, proving the tracker accepts real
     detector output unchanged.

DESIGN: TWO MECHANISMS, BOTH TEXTBOOK
-------------------------------------
Resist building a traffic simulator. Two orthogonal, explainable mechanisms
cover every case.

MECHANISM 1 — LONGITUDINAL: THE INTELLIGENT DRIVER MODEL
  Five parameters, ~20 lines, universally recognised. Any agent with the ego
  (or another agent) ahead in its own path follows it:

    a = a_max * [ 1 - (v/v0)^4 - (s*/s)^2 ]
    s* = s0 + v*T + v*dv / (2*sqrt(a_max*b))

MECHANISM 2 — LATERAL/CROSSING: A THREE-STATE GAP-ACCEPTANCE FSM
    APPROACH -> YIELD -> COMMIT
  Decided on a time gap at the conflict point against a per-class critical gap.
  Commitment is ONE-WAY, which is what humans actually do.

STATE VARIABLES PER AGENT
  mode              CRUISE, FOLLOW, YIELD, COMMIT, EVADE
  perceived_ego     Ego state delayed by reaction_time_s (a small ring buffer)
  committed         Latched true on entering COMMIT; never re-opens
  conflict_s        Arc-length of the crossing point on the agent's own path
  gap_at_decision   Recorded for telemetry and for explaining the decision

DECISION RULES
  1. Project the ego to the conflict point at its current speed -> t_ego.
     Project the agent -> t_agent.
  2. gap = t_ego - t_agent. If |gap| > critical_gap -> COMMIT and stop
     reacting to the ego.
  3. If 0 < gap < critical_gap and not committed -> YIELD: decelerate at
     b_comfort to stop before the conflict point.
  4. If the ego is ahead in the agent's own corridor -> FOLLOW under IDM.
  5. If TTC to the ego drops below emergency_ttc_s -> EVADE: hard brake, and
     for pedestrians and cattle, reverse the crossing direction.
  6. ALL of the above act on perceived_ego, never on instantaneous truth.

PER-CLASS PARAMETERS  (six numbers per class in config/object_profiles.yaml)
  CLASS           v0    T(gap)  critical_gap  reaction  b_comfort  YIELDS?
  ---------------------------------------------------------------------------
  Pedestrian      1.4     —        2.5 s       0.6 s       —       Usually;
                                                                   darts on a
                                                                   large gap
  Cattle          0.8     —        6.0 s       2.5 s       —       Rarely;
                                                                   mostly ignores
  Motorcycle     12.0   0.8 s      1.2 s       0.4 s      3.5      Assertive,
                                                                   small gaps
  Auto-rickshaw   9.0   1.0 s      1.5 s       0.5 s      3.0      Assertive
  Car            12.0   1.5 s      2.5 s       0.8 s      2.5      Normal
  Truck / bus     9.0   2.0 s      4.0 s       1.2 s      1.5      Sluggish,
                                                                   large gaps

THAT IS THE WHOLE MODEL.
